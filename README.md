# Goemon's Great Adventure: decompilation

A matching decompilation of **Goemon's Great Adventure** (Nintendo 64, USA, 1999), known in Japan
as *Ganbare Goemon: Dero Dero Dōchū Obake Tenkomori*. The C in this repository builds back into
the original ROM byte for byte:

    goemonsgreatadv.us.z64    sha1 9f9e860816f9e2a68bb5f4f56086e0c7450c64d7

## History

Every file here arrives in one commit because the work was done in a private repository first.
Its first commit was on 2026-09-28 and its last on 2026-10-20 (UTC): about three weeks from the
first commit to the finished decompilation.

## State

- **Code:** all 5,838 functions are C, and each matches the original instruction for
  instruction. No game code is left in assembly. Only the boot code (IPL3) and the RSP microcode
  stay binary, as in the other N64 decompilations.
- **Names:** every function, global, struct field and parameter has a name, taken from the
  game's own strings, tables and behaviour.
- **Assets:** extracted from your ROM into real formats (PNG textures, models and tables as C,
  scenario scripts as text, sound banks and samples) and rebuilt from them byte for byte.
- **Headers:** each function is declared once, in its module's header.
- **FAKE marks:** 145 spots where the C is shaped to match the original compiler's output. 122
  are kinds the sm64 and Ocarina of Time decompilations also keep; 23 are kept fakematches. Each
  is listed with its precedent in `canon-decompilation-tools/fake_kept.txt`.

## Building

You need your own copy of the game. The full steps, for Windows and macOS, are in
[`canon-decompilation-tools/README.md`](canon-decompilation-tools/README.md). In short:

    git clone -c core.autocrlf=false -c core.eol=lf <this repository> Goemons-Great-Adventure-Decomp
    cd Goemons-Great-Adventure-Decomp
    # put the game here as baserom.us.z64
    python -m venv .venv
    .venv/Scripts/python -m pip install -r requirements.txt     # .venv/bin/python on macOS
    .venv/Scripts/python canon-decompilation-tools/build_rom.py --setup
    .venv/Scripts/python canon-decompilation-tools/build_rom.py

The build ends by printing both hashes, the decompressed ROM's and the ROM's, each with `MATCH`.

## Layout

| Path | What is there |
|---|---|
| `src/` | The game's C: the main program and its overlays, and `src/tlb/` for the code files in the game's archive |
| `include/` | Headers: structures, enums (`enekind.h`: the 576 enemy kinds), one header per module |
| `assets/` | Generated by the build from your ROM; never committed |
| `canon-decompilation-tools/` | The build, the asset codecs, and the matching tools |
| `lib/` | libultra and zlib, from their own sources (submodules) |
